# D1 结构化搜索

## 目的

D1 从安全 fragment 出发，让 libFuzzer 组合 API/lifecycle action，自动发现 primary contract objective，并完成 decode、minimize 和独立 replay。`update_hook` 是 formal 目标，`create_scalar_function` 是跨 API smoke。

## 输入

- `experiments/corpus/d1/update-hook/safe-fragments.jsonl` 与 `experiments/corpus/d1/scalar-function/safe-fragments.jsonl`；
- `experiments/configs/d1-campaigns.toml`、`d1-objectives.toml`；
- committed source、deployment SHA-256、image digest 和 `nightly-2026-07-08`（除非新 revision 显式更新）；
- 新的外部 run artifact root。

## 禁止输入

禁止完整危险 seed、公开 PoC 的编码/改名副本、样本角色、预期结果和历史漏洞编号。只有 `BW-LIFE-001`/`BW-LIFE-002` 是 primary；progress、secondary、panic、ASan、timeout 与 tool error 不得冒充搜索成功。

## 前置检查

1. `tools/experiment/run-d1-formal.sh`、`run-d1-scalar-smoke.sh`、`verify-d1-formal.sh` 存在且可执行。
2. safe corpus 通过代码中的 `CorpusPolicy`；每次 iteration 重建 connection、runtime/oracle/callback 状态。
3. formal 使用新 run root，不覆盖历史 artifacts。
4. 当前隔离工作树的 rusqlite benchmark 独立 `Cargo.lock` 无法通过脚本内部的 `cargo --locked` 构建，所以**当前 commit 的新 D1 formal 为 Blocked**。下面命令是已核对的真实入口，不代表最新 gate 已执行。

## 精确命令入口

正式 `update_hook`：

```bash
tools/experiment/run-d1-formal.sh \
  --repo-root . \
  --runs-root "${BW_RUNS_ROOT:?}" \
  --commit "${BW_CODE_COMMIT:?}" \
  --deployment-sha256 "${BW_DEPLOYMENT_SHA256:?}" \
  --image-digest "${BW_IMAGE_DIGEST:?}" \
  --rustup-toolchain nightly-2026-07-08 \
  --campaigns 30 \
  --cpu-minutes 30 \
  --safe-cpu-minutes 30
```

formal hard-gate 校验：

```bash
tools/experiment/verify-d1-formal.sh \
  "${BW_RUNS_ROOT:?}/${BW_FORMAL_RUN_ID:?}"
```

第二 API smoke：

```bash
tools/experiment/run-d1-scalar-smoke.sh \
  --repo-root . \
  --runs-root "${BW_RUNS_ROOT:?}" \
  --commit "${BW_CODE_COMMIT:?}" \
  --deployment-sha256 "${BW_DEPLOYMENT_SHA256:?}" \
  --image-digest "${BW_IMAGE_DIGEST:?}" \
  --rustup-toolchain nightly-2026-07-08 \
  --campaigns 3 \
  --cpu-minutes 5
```

完整性和跨 run 汇总：

```bash
cargo run -p bw-experiment --bin bw-verify-run --locked -- \
  "${BW_RUNS_ROOT:?}/${BW_FORMAL_RUN_ID:?}"

cargo run -p bw-experiment --bin bw-d1-summary --locked -- \
  "${BW_RUNS_ROOT:?}/${BW_FORMAL_RUN_ID:?}" \
  "${BW_RUNS_ROOT:?}/${BW_SCALAR_RUN_ID:?}"
```

## 输出

每个 finalized run 保存 manifest、campaign records/counters、原始 artifact、decoded actions、minimized witness、20 次 replay summary、finding、stdout/stderr、summary、`COMPLETE` 与 checksum。formal 的最低门槛是 30 个 campaign、至少 18 个 primary、每个 primary replay 20/20、三阶段 witness 完整、safe-only artifact 为 0；timeout 进入分母。

## 失败分类

`no_primary`、`timeout`、`tool_error`、`crash_without_primary`、`invalid_sequence`、`replay_failure`、`safe_control_failure`、`integrity_failure` 分开记录。benchmark lock 或 fuzz toolchain 失败属于 `build_or_stage_blocked`，不是方法阴性。

## 结果归档

脚本拒绝复用 run ID；先执行 hard-gate 和 checksum 校验，再登记 `artifact:run:{run_id}`。归档必须保留 seed、CPU 预算、toolchain、deployment/config hash 和 objective policy hash。

## 清理

运行后删除 fuzz build cache 和 `.partial` 中可重建 corpus 副本；保留失败日志、代表 artifact、minimized/replay 证据和 finalized run。不得把 libFuzzer 变异 corpus写回版本化 safe seed。
