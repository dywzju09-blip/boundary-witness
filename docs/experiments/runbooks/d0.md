# D0 确定性动态回放

## 目的

D0 使用已知序列和同源对照，验证 static facts、runtime trace、callback-retention Contract、oracle、compile check、sanitizer/native outcome 与 checksum 归档能否闭环。它不证明系统能主动搜索触发条件。

## 输入

- `experiments/configs/d0-cases.toml`：12 个匿名 case，10 个运行项、2 个 compile-check 项，每个 formal 运行项重复 20 次；
- `experiments/ground-truth/d0-cases.toml`：只供矩阵一致性检查和事后评估；
- `contracts/callback-retention/contract.toml`；
- `artifact:dataset:d0-rusqlite-callbacks:staged`：与目标 commit 对齐的可执行文件、static facts 与 compile-check source；
- `code_commit`、deployment SHA-256、config SHA-256、工具链和 image digest。

## 禁止输入

runner/oracle 不得读取 scenario、expectation、历史漏洞标签或已生成 finding；不得以路径名向运行进程泄漏角色；不得把一次 crash 预先标成 confirmed violation。

## 前置检查

1. 工作树 clean，commit、toolchain、Contract/config hash 已写入 run manifest。
2. 运行环境为 Linux；formal 使用真实 image digest，不使用含糊的环境名。
3. staged artifact 与 matrix 的 case ID 一一对应，static facts 通过 `bw validate --kind static`。
4. 当前仓库存在 `bw-d0` 和 `tools/experiment/build-d0-targets.sh`。当前隔离工作树中的 rusqlite benchmark 独立 `Cargo.lock` 尚不能通过 `cargo --locked` 检查，因此 **artifact staging 为 Blocked**；在锁文件对齐并重新验收前，不得声称当前 commit 可从源码完成 D0 formal。

## 精确命令入口

矩阵结构检查（会读取 ground truth，但不执行 detector）：

```bash
cargo run -p bw-experiment --bin bw-d0 --locked -- \
  --check-matrix experiments/configs/d0-cases.toml \
  --ground-truth experiments/ground-truth/d0-cases.toml
```

构建 runner 变体；该脚本必须在固定 Linux 环境中运行：

```bash
tools/experiment/build-d0-targets.sh \
  --repo . \
  --config experiments/configs/d0-builds.toml \
  --out "${BW_ARTIFACT_ROOT:?}/d0-builds"
```

当 staged dataset 的阻塞解除后，先 preflight，再使用完全相同的参数执行 formal：

```bash
cargo run -p bw-experiment --bin bw-d0 --locked -- run \
  --mode preflight \
  --commit "${BW_CODE_COMMIT:?}" \
  --deployment-sha256 "${BW_DEPLOYMENT_SHA256:?}" \
  --config-digest "${BW_D0_CONFIG_SHA256:?}" \
  --image-digest "${BW_IMAGE_DIGEST:?}" \
  --stable-toolchain "${BW_STABLE_TOOLCHAIN:?}" \
  --compiler-nightly "${BW_COMPILER_TOOLCHAIN:?}" \
  --repo-root . \
  --runs-root "${BW_RUNS_ROOT:?}" \
  --contract contracts/callback-retention/contract.toml

cargo run -p bw-experiment --bin bw-d0 --locked -- run \
  --mode formal \
  --commit "${BW_CODE_COMMIT:?}" \
  --deployment-sha256 "${BW_DEPLOYMENT_SHA256:?}" \
  --config-digest "${BW_D0_CONFIG_SHA256:?}" \
  --image-digest "${BW_IMAGE_DIGEST:?}" \
  --stable-toolchain "${BW_STABLE_TOOLCHAIN:?}" \
  --compiler-nightly "${BW_COMPILER_TOOLCHAIN:?}" \
  --repo-root . \
  --runs-root "${BW_RUNS_ROOT:?}" \
  --contract contracts/callback-retention/contract.toml
```

finalized run 完整性检查：

```bash
cargo run -p bw-experiment --bin bw-verify-run --locked -- \
  "${BW_RUNS_ROOT:?}/${BW_RUN_ID:?}"
```

## 输出

`artifact:run:{run_id}` 至少包含 `manifest.json`、`summary.json`、`findings.jsonl`、replay/compile-check records、traces、child logs、`COMPLETE` 和 `checksums.sha256`。contract finding、ASan、native crash、panic、timeout、invalid input 与 tool error 分开记录。

## 失败分类

- `input_error`：matrix、Schema、Contract 或引用错误；
- `build_or_stage_blocked`：锁文件、toolchain、artifact 或 compile-check 准备失败；
- `timeout`、`tool_error`、`invalid_input`：进入独立统计，不是 negative；
- `integrity_failure`：缺文件、额外文件、symlink 或 checksum mismatch；
- `control_failure`：安全/修复对照产生核心 finding；
- `incomplete_evidence`：只有 crash 或 exposure，未闭合 oracle 证据链。

## 结果归档

只有没有 `.partial` 后缀、存在 `COMPLETE` 且 `bw-verify-run` 通过的目录才能登记为 `artifact:run:{run_id}`。结果文档必须绑定 [数据对齐字段](../data-alignment.md)，并明确 D0 是已知序列回放。

## 清理

删除 `.partial` 中可重建的 build/cache 前先保留 manifest、日志和失败分类；不删除 finalized run。每个 replay 的临时工作目录由 runner 隔离，不得复用到下一 case。清理完成后记录删除范围和 retained artifact ID。
