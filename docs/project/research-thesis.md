# 研究主线与创新点

本文是**唯一的方向权威**。路线图、范围边界、当前状态都必须服从本文；任何实现如果不能落到本文的某一条创新点上，就不该做。

当前阶段仍是 **V3.2.x core-effect hardening**，V3.3 gate 未通过。本文描述的是目标结构，不是已达成的能力。

## 1. 论题

> **一个安全 Rust API 包装外部组件时的健全性，等价于「Rust 侧类型层契约」与「外部侧跨界实际行为」之间是否存在逐维错配。判别这个错配——而不是怀疑它——必须联结边界两侧的事实。**

「判别」这个词是 2026-07-31 外部基线对照（[结果](../experiments/results/gate0-baseline-comparison-2026-07-31.md)、[误报归因](../experiments/results/gate0-yuga-precision-triage-2026-07-31.md)）之后改的，原表述是「检出」。**那次实验否定了原立论。**

实测：Yuga 在 rusqlite 0.26.1 上报出公告 7 个函数中的 5 个，理由直指回调值活得比借用长、被赋给外部对象，且这 5 条在修复版精确消失。**所以「现有工作不会报出这一持有期缺陷」不成立，只用 Rust 侧证据也能怀疑到它。**

但同一次运行里，它的 13 条报告有 8 条不对应公告缺陷，逐条读源码后**根因完全统一**：它无法区分

- 值被**存进一个受借用检查器约束的 Rust 结构体**（`MappedRows<'stmt, F> { rows, map: F }`），与
- 值被**跨边界交给一个外部持有的槽位**

两者在 Rust 侧看起来都是「一个泛型值活得比借用长，且出现在外部指针附近」。Yuga 的报告原文把 `f` 说成「被赋给 `ffi::sqlite3_stmt`」，而 `f` 其实只是和持有该指针的字段同处一个结构体。

**这个区分正是边界另一侧才能给出的。** 核心抽象仍是**逐维契约错配**，生命周期只是其中一维；变的是贡献所在：不在于能不能报，而在于报得准不准。

## 2. 统一模型

每个 Rust→外部的交出点（hand-off）由稳定身份 `(crate, version, foreign_symbol, call_site)` 标识，两侧各产出事实：

| 维度 | Rust 侧契约（类型/签名层，可证） | 外部侧实际行为（LLVM IR，可测） |
| --- | --- | --- |
| 持有期 | 回调 bound 是 `'a` 还是 `'static` | 指针是否逃逸到返回后仍存活的存储 |
| 别名与可变性 | 来源是 `&T` 还是 `&mut T`、参数是否 const | 是否被写穿 |
| 线程 | 是否要求 `Send` / `Sync` | 是否被另一线程可达 |
| 重入 | 交出时是否持有 `&mut` 或运行时借用 | 是同步调用还是存起来稍后调用 |
| 展开 | trampoline 是否有 `catch_unwind` | 调用点是否处于不可展开上下文 |
| 释放责任 | 分配与释放是否同侧 | 是否有配对 free 回调、是否真调 |
| 值域不变量 | 返回值被当作何种 Rust 类型 | 实际可能返回的值域 |
| 初始化 | 传入 buffer 的初始化状态假设 | 实际写入范围 |

**错配 = 某一维上契约允许的比实际发生的宽。** 判定器对每一维执行同一操作：取两侧事实、比较、产出候选与见证计划。

这是框架性的来源：新增一个缺陷类等于新增一维，而不是新增一个 lint。

## 3. 三条创新点

按可辩护程度排列。实现优先级与此一致。

### N1 — 跨界判别：把「怀疑」变成「判定」

主线论点，2026-07-31 后由「检出」改为「判别」。

只用 Rust 侧证据可以**怀疑**这类缺陷，但无法把跨界交出与 Rust 内部存储分开，因为两者的 Rust 侧形状相同。贡献是：问题形式化、两侧事实模型、逐维判定框架，以及**用外部侧证据消除该误报类**。

验收是**精度对照**：同一 corpus 上，本系统与先验工具各自的误报率，且误报要能归因。首个数据点见 [误报归因](../experiments/results/gate0-yuga-precision-triage-2026-07-31.md)——单 crate 上 Yuga 5/13、本系统 5/5，但 **n=1 且该 crate 参与过本系统开发，不构成证据**，必须在未调优 crate 上重测。

### N2 —（已撤销）消除人工 API 清单

原主张：现有 FFI 分析工具需要人先声明哪些外部符号是回调注册，本系统结构化推断该角色。

**2026-07-31 撤销。** Yuga 不使用任何 API 清单就报出了 5/7，该主张对这一缺陷类不成立。结构化推断仍会实现（见 [roadmap](../roadmap/roadmap.md) P1），但作为**工程属性**，不作为创新点，也不再需要以消融实验为其立论。

### N3 — 定向见证：把「可能不健全」降为「已确认可触发」

不是盲测。见证由静态已证明的那一条具体契约违反反推构造，oracle 判定的是契约违反而不仅是崩溃。

外部基线之后这条更重要：先验工具给出的是 "**probably** assigned"、"**potential** use-after-free"，而 Yuga 论文自述这类缺陷难以动态检测。把猜测变成可运行的确认，目前无人做。

## 4. 相关工作定位

必须在论文中精确区分，尤其是前两行。

| 工作 | 覆盖 | 与本系统的边界 |
| --- | --- | --- |
| Yuga（TSE 2024） | 函数签名上的生命周期标注错误 | **已实测：它能报出本项目主线缺陷类的 5/7，修复版精确消失。**「它不建模外部持有者所以不会报」是错的，不得再使用该表述。差别在精度：同一 crate 上 13 报 8 条不对应公告，根因统一为无法区分「存进受借用检查器约束的 Rust 结构体」与「跨界交给外部槽位」。它论文自述这类 bug 难以动态检测，N3 正是对此的推进 |
| Rudra（SOSP'21） | panic safety、higher-order safety invariant、Send/Sync variance | 技术路线同为 HIR+MIR，但三类缺陷均为 Rust 内部，不含跨界持有期 |
| FFIChecker（ESORICS'22） | Rust/C FFI 堆内存管理，LLVM IR 污点分析 | 判 alloc/dealloc 错配与 double free，不判安全 API 契约强度。释放责任维度与其重叠，**不作为创新点** |
| ACORN / 多语言 Rust（2025） | Rust 与 C 均译为 Wasm 作统一 IR | 本系统不做全量翻译，只做有界查询，须在论文中说明代价与精度取舍 |
| MiriLLI（ICSE 2025） | Miri + LLVM 解释器联合执行，跨 FFI 的 UB 实证研究 | 是 study 而非检测器。其结论「Miri 看不进外部函数」是本系统 oracle 选型的直接依据 |
| deepSURF（S&P 2026） | 静态分析 + LLM 生成 harness + fuzzing | 盲测求崩溃；本系统是定向见证求契约违反。**撞车风险最高，必须在评估中并列对比** |
| PinChecker（2025） | 合成程序违反 Pin API 契约 | 思路相近但对象是 Pin，不涉跨语言 |

## 5. 评估设计

以下每一项缺失都会削弱对应创新点。

1. **与 Yuga、FFIChecker 在同一 corpus 上并列的精度对照**，规模不少于 10–20 个 FFI crate。**这是 N1 现在的核心证据**：召回相当时，误报率的差距与误报归因才是贡献所在。单 crate 数据不构成证据。
2. **未调优 crate 上的评估**。开发期使用过的 crate 不能作为精度证据——本系统在 rusqlite 上的 5/5 存在过拟合嫌疑，必须在未参与开发的 crate 上复现才算数。
3. **消融**：关闭外部侧分析后精度回落多少。这是 N1 的机制证据——若关掉外部侧精度不变，说明贡献不来自跨界证据。
4. **已披露公告上的召回**：报告命中比例与**漏报原因**。漏报必须分析，不得只报命中。
5. **生态级扫描**：具备可分析外部源码的 FFI crate 全集。
6. **新发现与披露流程**。

## 6. 已确立的方法学纪律

以下几条来自本项目已发生的返工，违反任何一条都会产出「看起来正常但什么都没判出来」的结果。

- **缺证与健全必须可区分。** 没有事实不等于安全。任何判定都要有第三态。
- **两半齐才是缺陷。** 单侧证据只产出候选，不产出结论。
- **join key 必须是被判定对象本身的身份，不是分析产物的切分单位。** 候选按边界切分，会把同一函数的两半分到不同候选。
- **改判定器必须做非空性验证**：故意破坏判据的一半，确认对应断言失败且失败落在预期位置。
- **模型与 schema 必须双向比对**，逐条手写断言会漏。
